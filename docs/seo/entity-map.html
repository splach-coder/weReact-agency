How to keep it consistent

NAP must match the Google Business Profile exactly

Name, address and phone in src/config/site.ts must be the same, character for character, as the verified profile (CID 906947470338054436): WeReact agency, Marrakech 40000 (region Marrakech-Safi, MA), +212 602-258009, hours Mon–Fri 9:00–18:00.

If one changes, change it on the profile and in site.ts on the same day, then bump FACT_SHEET_REVIEWED_AT in src/lib/site-index.ts so the AI info page shows the new date.

One name everywhere: “WeReact agency”

Use siteConfig.name / business.legalName in markup, profiles and directories. “WeReact” is only the short name (alternateName).

Known exception to fix: the inline BlogPosting on post pages names the publisher “WeReact” and the author “WeReact Editorial Team”. Switching to createBlogPostingJsonLd() fixes both.

Reference, never repeat

New nodes point at the business with { "@id": "https://www.wereact.agency/#business" } (export ENTITY_IDS). Never copy the address, phone or name into another node. Never change an existing @id: other pages and search engines already point at it.

Adding a city, topic or profile

Look the item up on Wikidata (wbsearchentities, then wbgetentities to check “instance of” and the Wikipedia sitelinks), add it to src/lib/entities.ts with a one-line note, and add the city name to business.areaServed. Never add an ID from memory.

Add a profile to business.sameAs only if WeReact owns it and it shows the same NAP.

What to add later, and only then

Founder: a Person with its own @id (e.g. /#founder) linked by founder, only if the owner chooses to be named publicly on the site.

Reviews and ratings: only real reviews, shown on the page with a link to their source (e.g. the Google profile). Do not mark up self-collected or invented ratings.

Other facts (founding date, legal registration, price range): only once they are published on the site.

Check after every change

Run npm test (src/lib/seo.test.ts checks the references), then paste a home, service and case-study URL into the Schema Markup Validator and Google’s Rich Results Test.

Run node scripts/seo/link-audit.mjs <base-url> against a build to catch links to redirects and pages with no contextual links.

Related: /llms.txt and /{locale}/ai-info are generated from the same data (src/lib/site-index.ts, src/lib/llms-txt.ts), so the facts there cannot drift from the markup.
